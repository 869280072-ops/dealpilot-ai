## B2 修复与证据

- 新增 `mutation_receipts`，唯一键 `(user_id, request_id)`；新增价目和生成报价必须提交 UUID `requestId`。
- 同一用户的相同请求键与相同内容返回已保存结果；同键不同内容/操作拒绝。回执、业务数据及初始报价历史在同一事务中提交。
- 浏览器为失败/结果不确定的请求保留相同请求键；成功后下一次主动操作使用新键。相同请求键不会创建第二份报价；新键仍允许主动创建独立草稿。
- 活跃价目以团队、服务、币种和标准化名称（trim/lower）建立部分唯一索引。即使请求键不同，相同单价复用原项目；同项目不同单价拒绝，不擅自覆盖。
- 所有回放都重新检查当前用户、membership、owner 权限和需求归属，不以幂等缓存替代鉴权。
- 真实 PostgreSQL 回归：8 次价目请求（混合相同/不同请求键）只保留 1 个活跃项目；8 次同键生成只创建 1 个草稿、1 条初始历史，单价 10000 分的总额仍为 10000 分；改请求内容、跨用户回放均拒绝。主动新键创建独立草稿仍可用。

## AI 重复调用与费用保护

工作台 API 使用 PostgreSQL `ai_runs` 持久预留与唯一索引，键包含用户、需求 id/revision、模式和包含安全策略/模型/endpoint 的配置指纹（不保存 API Key）。

- 预留及预算检查使用数据库事务 advisory lock，适用于多个应用进程；模型请求在事务外执行，不长时间持有数据库锁。
- 同版本同配置：进行中返回 409 说明，不启动第二次请求；成功后重新鉴权并复用同一分析。
- 每用户只允许 1 个未完成 Live 调用；不同需求也不能绕过该并发限制。
- 默认滚动额度：每用户 1 小时 5 次、24 小时 20 次、全站 24 小时 100 次。配置来自 `.env.example` 的三个 limit 变量；0 阻止新的 Live 预留，越限返回 429。请求开始前检查；失败/不确定请求也占用预算。
- 出错后持久记录 failed，重复请求不会自动重试。进程崩溃留下 running 时也不自动过期重发，避免第一次其实已计费却再次调用；需管理员先核对提供方记录。
- 需求在模型调用期间修改或权限撤销时，写回仍重新鉴权、检查版本。仅内部失败状态记账可清理本次已授权预留，不向已撤权用户返回结果。

**8 并发实测（真实 PostgreSQL + 模拟提供方）：**

| 场景 | 结果 |
|---|---|
| 8 个同用户/同需求版本/同配置请求同时到达 | 1 个完成、7 个处理中拒绝；提供方模拟函数仅调用 1 次 |
| 完成后再发 8 次相同请求 | 全部复用同一分析 id；累计提供方调用仍为 1 |
| 新数据库连接再次请求 | 复用同一结果；累计调用仍为 1 |
| 提供方模拟超时后重试同版本 | 失败状态保留；不发起第二次调用 |
| 用户小时/日额度、全站额度已达限制 | 无提供方调用；全站额度也约束另一个用户 |
| 已有 Live 预留未完成，发起另一需求 | 拒绝；不会增加提供方调用 |

额度限制的是请求预留次数，不是货币预算；仍需在真实提供方设置消费上限。代码没有执行自动重试，也没有购买或开启任何收费 API。

## 迁移与兼容性

追加 `0003_odd_payback.sql`、Drizzle journal 与 snapshot：新增 ai_runs、mutation_receipts；分析新增 policy_version；价目新增 archived_at 和活跃唯一索引。

- 相同业务键、相同单价的历史重复价目保留最早一条，其余归档，不删行。
- 相同业务键但不同单价会使**整个迁移事务回滚**，不擅自选价。需先备份并人工核实、规范冲突价目后再运行迁移；不能把失败当成功或自动删数据。
- 原有报价与历史保存价格快照；迁移不会重算或覆盖。
- 实际迁移脚本验证了：先应用已有 0000—0002 并写虚构历史数据；冲突时新增 DDL/数据和账本完整回滚；修正测试夹具价格后升级成功、归档一条重复；报价和历史逐字段不变；再次 migrate 为 no-op。

接口兼容性：`saveCatalog` / `generateQuote` 新增必填 `requestId`，旧客户端会收到 400，必须同步更新；不能让旧版业务进程继续运行并绕过新 AI 调用保护。

操作命令仍是 `pnpm db:migrate`，仅允许经核实的开发/测试目标。本轮没有连接生产数据库。
